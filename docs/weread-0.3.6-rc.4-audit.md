# 微信读书 for Kindle 0.3.6-rc.4 检查报告

日期：2026-10-28。对象为用户上传的 `③kindle-weread-0.3.6-rc.4-install 2.zip`，不是本项目此前的 `0.1.0-alpha.1`。用户主动删除了一个大字体文件，本报告不把这项精简记成软件原版的缺陷。

**结论：安装包中的核心程序完整，采用独立 ARM 原生程序及原生书架启动入口。其发布说明声明的阅读功能已明显多于本项目当前 alpha，适合优先评估复用；但它并未达到与 MiuRead 或 Android 功能完全一致的状态。现在能确认的是若干发布说明明确承认的限制，不能把静态检查写成实机验收。**

包内没有可构建的应用源码。当前已修正 ZIP 文件名编码、移除 macOS 附带元数据，并完成初步功能对照；**尚未修改其进度、笔记、翻译等核心功能**。继续补齐这些功能需要对应源码、构建方式和真实账号/设备回归条件。

## 安装、依赖和字体

- 原始 ZIP 15,978,806 字节，97 个条目；包含 `documents`、`extensions/weread`、`weread`、`fonts`。实际提取 43 个非 AppleDouble 文件，其中一个是 `.DS_Store`；没有空的核心程序。
- `weread/bin/kindlehf` 和 `weread/bin/kindlepw2` 各含 `weread_ui`、`script-runtime`、`device-info`、`fb-session`、`framework-session`、`fsr-session`、`screen-refresh`。主程序分别为 8,274,196 / 8,172,256 字节，均为静态链接、去除符号的 ARM ELF；前者采用 hard-float ABI，后者采用 soft-float ABI。
- 书架入口 `documents/微信读书.sh` 设置 `WR_LAUNCH_ORIGIN=library` 后调用 `weread/start.sh`。后者按系统 loader 选择上述两种 runtime。KUAL 是另一种入口，安装说明也允许 Scriptlets，不能据此说 KUAL 必须安装。
- 包中没有 KOReader 插件目录或 KOReader 安装步骤。静态结构与独立原生运行方式一致；最终仍应在没有 KOReader 的 KPW5/Vera 上验收启动、退出、休眠和显示。
- `starting-v2.html/js` 使用 Kindle Pillow/nativeBridge，只负责“进入中”窗口，不能把它当成完整阅读器的网页源码。大部分 shell 文件是调用 `script-runtime` 的分派外壳；两个 Lua 文件仅有 `Protected Lua resource; executed by script-runtime.` 占位说明。
- 上传包保留 `AlibabaPuHuiTi-3-55-Regular.ttf`（8,532,824 字节），没有仓库中的 `LXGWWenKai-Regular.ttf`（25,575,676 字节）。程序可见两者路径，含 `ui reading font fallback=1` 和“原字体不可用，已使用默认字体”提示；更新说明也声明字体回退。**有回退迹象不等于已证明删除字体后所有页面均能正常显示**，需要在无旧字体缓存的设备上验证。
- `assets.sha256` 中启动页 HTML、JS、Logo 三项均匹配。该清单只覆盖启动资源，不能用它证明整包来源真实性。

## 本次已修正的打包问题

原始 ZIP 的全部 97 个条目都未设置 UTF-8 文件名标志，但中文名称实际以 UTF-8 字节保存。遵循 ZIP 默认 CP437 解码的工具会显示 `Γæó...`、`σ╛«...` 一类乱码；保留这种名称复制到 Kindle，可能导致书架入口显示和查找不一致。

已生成 `dist/weread-inspection/weread-0.3.6-rc.4-font-reduced-utf8.zip`：

1. 正确标记中文路径编码，去掉外层安装包目录，解压后直接得到 `documents/`、`extensions/`、`fonts/`、`weread/` 和两份说明。
2. 移除 `__MACOSX`、AppleDouble 及 `.DS_Store` 等附带文件，保留 42 个实际交付文件。
3. **42 个文件的内容 SHA-256 与原包全部一致**；两个 ABI 的全部程序、脚本、证书、资源和保留字体均未改动，也未补回用户删除的字体。
4. 完成新旧 ZIP CRC、路径集合、UTF-8 标记、逐文件哈希及启动资源清单验证。整理包的 SHA-256 在同目录 `SHA256SUMS` 和机器证据中。

这是包结构修复，不是功能升级版本。沿用原作者安装/升级说明，其中要求升级后重新登录并联网核验需要离线阅读的书籍。未在 Kindle 上安装此包，不能把它称为已实机验证的修复版。

## 核心功能补齐的顺序与当前阻塞

1. **先取得同版本源码并复现构建**：确认 `weread_ui`、`script-runtime` 及设备辅助程序的来源和构建方式。当前 GitHub 历史只有初始化、UI 规格书和摊平的上传文件，上传 ZIP 也没有实现源码；可编辑的启动页不是核心功能实现位置。
2. **优先进度和笔记正确性**：使用同账号、同书同版本，覆盖 Kindle→Android 与 Android→Kindle、改字号、目录变化、离线重开；笔记覆盖超一页大集合、增量/分页分离、更新/删除和未知写入结果，防止重复或丢失。
3. **补新译文生成，核对周统计入口**：在现有会话/会员/队列上扩展，保留超时、取消、限频和已有译文；周统计先确认占位路径是否可达，再补真实数据及跨日过期处理，不用本地未确认时间冒充云统计。
4. **再评估原版 PDF、OCR 和 Android 扩展能力**：这些可能需要新阅读引擎、服务或设备接口，按实测需求实施，不通过伪造按钮宣称补齐。
5. **KPW5/Vera 回归**：无 KOReader、无已删除字体及旧字体缓存的启动；登录后阅读、离线重开、换字体、退出、短睡/深睡、合盖、USB 连接及恢复。

以上为工作顺序，不是已完成清单。起点、长佩及独立 MiuRead 的原目标保留；当前不把已有软件的缺口转移成修改本项目 alpha 后宣称“补好了这个软件”。
