## 2. P0-A：原生书架启动验证

**目标**：把“像书架里的 app”转换为可重现的真机结果。

已知前置资料：KPW5，使用 Vera 越狱。仍需补齐完整固件版本、Vera 版本及可用启动方式。MiuRead 是交互参考，无需安装；KUAL 安装状态未知且不默认是必需组件，KOReader 明确不作为前置。无需收集完整序列号。

验证步骤：

1. 在不依赖 KOReader 的测试组合中，确认选定应用能正常启动与退出；记录二进制/运行时、版本、来源及依赖清单。
2. 核对 Vera 环境实际提供的启动方式、是否有 KPM 与可用 scriptlet 注册机制，确认能否安装独立书架项目项；不假设 KPM 已安装或其钩子已足够。
3. 检查书架索引、文档筛选及设备重启对入口可见性的影响。
4. 验证点击项目项后，进入指定项目页面或最近正文，不停在通用菜单或文件管理器。
5. 重复启动、退出和休眠唤醒，确认系统书架、触控和按键能恢复；记录已有阅读进程时的行为。
6. 验证移除项目后原有书籍与应用设置仍在，系统能够正常使用。不删除用户已有软件来制造测试条件。
7. 检查安装包、下载行为、进程和加载模块，确认没有捆绑、调用或下载 KOReader 运行时；仅隐藏其 UI 不算通过。

通过证据：目标版本清单、启动路径说明、实际操作记录、首次与再次启动耗时、退出及卸载结果。使用测试正文验证本项允许，但不能因此通过内容访问项。

停止条件：所需机制不支持目标固件，或只能做到多级菜单启动。此时说明阻塞并重新评估入口方案，不把“越狱成功”当成应用入口已经可用。

## 3. P0-B：起点与长佩的真实内容访问验证

**目标**：分别确认起点与长佩有哪些内容可以实际获得与阅读，以及通过什么方式。以下步骤和证据每个平台单独记录，不共享会话或凭据。

1. 先记录用户关心的书籍及章节类型，不收集账号密码到聊天或仓库。
2. 查明官方网页或受支持接口的可用方式，阅读实际访问条件；保留 TLS 验证。
3. 对免费章节验证：作品标识、目录顺序、章节标题、正文完整性、分页或分段情况、字符显示。与同一章节的官方展示人工对照，不能只看 HTTP 200。
4. 对登录验证：记录正常登录方式、验证码或其他交互依赖、会话过期方式、设备是否能完成流程。若借助手机，单独证明会话能否用于目标读取方式。
5. 对已购章节验证：仅使用测试者已有授权的章节；区分正文、试读片段和权限页；未购章节应产生正确状态，不触发订阅扣费。
6. 明确是否允许本地缓存、缓存何时失效及登出如何处理；在线访问成功不等于离线缓存可用。
7. 测试断网、会话过期、访问挑战、限流、章节失效或下架的处理。

通过证据：访问路径类别、域名、设备/浏览器或运行时版本、各能力的实际结果、正文核对结果及失败分类。不记录 Cookie、Token、密码，不提交受限正文作为公开测试夹具。

没有可用的已购章节路径时，必须标记“未支持”或“阻塞”；若用户首版必须读 VIP，则不能发布为满足该目标的版本。免费章节也应单独有真实验证，不能以本地示例代替。

长佩不能套用起点或 MiuRead 的接口、书籍 ID、登录方法或付费权益。分别检查官方目录与正文展示、试读/已购边界及缓存允许范围；对外说明时逐平台列出结果。

## 4. P0-C：阅读桥接与连续阅读验证

1. 对独立应用的候选排版与设备组件记录运行时、能力、版本和架构，先证明无 KOReader 依赖；不要用电脑上可运行代替 Kindle 兼容性。
2. 从实际支持的格式中选择章节交付方式，检查中文标点、段落、目录、跨章切换和排版后位置映射；不预设 Lua、HTML 或 EPUB 接口存在。
3. 更新目录及添加章节后验证旧位置仍可恢复；改变字号后仍回到原段落。
4. 验证缓存离线阅读、缓存写入中断、低存储空间及内容版本变化。
5. 检查网络等待时能否取消/返回，旧正文是否仍可读，以及休眠后是否停止请求。

通过证据：选定格式及理由、位置映射方案、章节跳转与休眠恢复记录、故障行为。合成内容可以覆盖格式及边界测试，P0-B 仍须另用真实内容完成。

## 6. 环境与开发准备边界

当前云环境可用于文档及后续逻辑、夹具、打包验证；不能等同于 Kindle 硬件环境。语言、工具链、测试框架和模拟器依赖均需按核实后的路线选择，不能继续沿用 KOReader 插件假设。

本轮资料读取通过环境已有 GitHub 访问完成，没有申请账号凭据或变更网络白名单。后续进行内容验证时按实际访问的官方域名检查环境网络权限；如受限，添加必要目的地，不关闭证书校验或绕过代理限制。

本轮不生成安装器、不调用 Kindle 系统工具、不注册真实书架项。MiuRead 项目身份已澄清；独立运行、原生入口与真实内容三个门槛未通过前，不投入完整产品界面和发布打包。
