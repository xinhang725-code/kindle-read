# MiuRead 独立化与原生书架入口

状态：项目文档，尚未进行移植或真机验证。用户已确认 MiuRead 本身是交付目标，不只是界面参考。

## 1. 目标与完成定义

在 KPW5、Vera 越狱环境中，原生书架显示 MiuRead 项目项，点击进入 MiuRead 的微信读书书架、首次授权流程或最近正文。它与起点阅读、长佩阅读并列交付，保持各自内容与账号边界。

此前“不依赖 KOReader”的约束继续适用：不要求安装 KOReader，不在包内隐藏 KOReader 运行时，也不通过快捷方式间接启动原来的插件。原生入口和宿主依赖替换必须同时完成。

允许复用许可兼容的独立库，也允许迁移 MiuRead 自身的业务代码；不能以移植之名删去其微信读书功能，再交付一个同名空壳或仅能读本地文件的程序。

## 3. 依赖替换清单

| 边界 | 已见线索或待审计能力 | 独立化要求 |
| --- | --- | --- |
| UI 与事件循环 | `ui/uimanager`、`ui/widget/*`、`ui/event`、`ui/time` | 独立绘制、控件、调度和事件循环；后台请求不能阻塞翻页或退出 |
| 设备与刷新 | `device`、`ffi/blitbuffer` | 真机触控、墨水屏刷新、休眠/唤醒、退出恢复；不调用 KOReader 设备服务 |
| 文件与日志 | `libs/libkoreader-lfs`、`logger` | 替换为可独立分发的实现；路径、原子写入和日志脱敏保持正确 |
| 阅读与位置 | 具体调用链待全量审计 | 替换宿主排版及导航；建立章节、段落与云端位置坐标映射，不能直接沿用页码 |
| 网络与授权 | 上游 Web/E-Ink 业务及运行时耦合待审计 | 迁移可复用业务，验证独立运行时的 TLS、授权、过期和取消处理 |
| 配置、缓存与升级 | 上游存储及 OTA 对插件布局的假设待审计 | 使用独立应用的版本/目录；不能通过上游插件更新覆盖已移植程序 |

优先评估“独立核心 + MiuRead 移植模块”；若审计证明以 MiuRead 独立分支为主更合适，可调整内部组织，但三个入口、微信读书用途与无 KOReader 要求不变。

## 4. 功能对照与分阶段验收

全部能力当前均未移植、未实测。以下是建议阶段，不是宣布已经支持，也不是默认删减功能。

| 功能 | 首轮要求 | 后续必须记录的结果 |
| --- | --- | --- |
| 原生入口、冷启动、退出 | 首个独立闭环必需 | 三个入口并存，无插件菜单和隐藏宿主 |
| 微信读书授权与账号书架 | 首个独立闭环必需 | 实际授权、会话过期、退出账号和正确账号书架 |
| 目录、正文获取/下载、阅读 | 首个独立闭环必需 | 真实有权访问的正文完整，不能用试读片段冒充完整书籍 |
| 缓存及本地续读 | 首个独立闭环必需 | 缓存许可允许时可离线读，退出/休眠后恢复位置 |
| 云端精确进度与阅读状态 | 迁移对照表必填 | 独立排版后的坐标转换、多设备冲突；验证前不能上传可能错误的位置 |
| 划线、想法、阅读时长 | 迁移对照表必填 | 分别记录可用、受限、阻塞或待实现，不能随界面复用宣称支持 |
| 搜索/书城、译文及双语、其他上游功能 | 固定版本后补齐全量清单 | 分别记录依赖、权限及实测结果，不能用当前摘要代替全量清单 |

每项记录上游版本、对应模块、独立实现方式、测试证据与限制。首个闭环只可称为 MiuRead 独立化预览；宣称“完整移植”前必须对已选上游版本完成全量对照。若需要把原功能延期或删减，写明范围供用户决定，不以“只参考体验”自动缩减。

## 5. 入口、数据与更新

- MiuRead 入口明确选择微信读书上下文，不依赖用户先打开起点或长佩应用。
- 数据按来源与账号隔离，保存自己的最近阅读；跨入口切换先保存旧上下文，避免串用会话或进度。
- 不直接改写用户原有 KOReader/MiuRead 数据。若后续提供导入，先备份并验证版本兼容、书籍 ID 和位置映射；不能直接导入旧页码作为新排版位置。
- 在没有受保护会话存储证据前不承诺持久登录；仍应支持通过安全授权重新进入账号书架。
- 独立版本更新不能自动跟随上游插件 OTA；更新包需明确运行时、目标设备和数据版本，校验后才能安装。
- 卸载任一应用仅移除对应入口和选定数据，不破坏另外两个应用；共用组件只有在无其他依赖时才可移除。

## 6. 验证顺序与交付证据

1. 固定上游版本，完成模块与许可审计，列出每项宿主依赖的替换方式。
2. 在受控、无 KOReader 的环境中验证独立 UI、中文排版、输入、生命周期及最小 MiuRead 页面。
3. 在目标 Kindle 上验证原生入口、单击直达、退出及重启后入口仍可用。
4. 验证真实微信读书授权、书架、正文获取、阅读和本地续读；不复用起点或长佩的成功记录。
5. 逐项迁移其他功能，验证来源隔离、数据兼容和独立更新。

交付证据包括包与依赖清单、固定上游版本/修改记录、真机启动记录、微信读书功能对照表、已知限制，以及许可要求的源码和通知。应用展示名和分发说明应明确这是修改/移植版本及其上游来源。

当前仅完成文档与部分依赖资料核对；尚不能承诺现有插件无需修改即可原生运行。若独立化出现阻塞，记录阻塞及可选处理，不把隐藏 KOReader 作为已满足目标的结果。
